# Agent instructions: impact.ai instrumentation

This repository holds what customers install in their own environments. Treat every artifact as running in a
customer's production cluster: it must never stop their workloads, never read their secrets, and never send values
that could contain secrets.

## Rules

- **Never break the customer's app.** Injection fails open (webhook `failurePolicy: Ignore`, short timeout, system
  namespaces excluded). The instrumentation stands down when the process already has another tracer.
- **Names, never values.** The reporter sends names only: no environment values, container arguments, ConfigMap or
  Secret contents, and only allowlisted annotations. Its RBAC never includes Secrets or ConfigMaps.
- **No privileged pods** by default. Images run as non-root where the Operator allows it.
- **Supply chain.** Pin base images by digest, Python packages by hash and npm packages by the integrity hash of their
  lock file (installed with `--ignore-scripts`: no package code runs in a build); build with provenance and SBOM; no
  credentials in images.
- **Node.js preload.** `nodejs/src` loads on Node 16 too and never throws: every failure is caught and reported in the
  `impact.setup` span. ES modules are traced only where `nodejs/qualification.json` proves it (`make qualify` writes it;
  `make test-nodejs-matrix` fails when a cell no longer says what it did), because the loader hook can break a library that
  was not tested (openai 4's ES module build). The image carries no provider SDK; its package called `openai` is a
  stand-in (`nodejs/shims/openai`).
- **Overhead.** An injected workload costs at most +1.5 ms of CPU per model call, +40 MiB and +2 s to start
  (`make overhead`, the canary in `make ci`, the full matrix in `make release`). Do not raise a budget to pass: find the cost.
  A Node.js workload's memory is read after both sides have collected all their garbage (`settle` in
  `python/tests/overhead/harness.py`), because V8's young generation grows by doubling and does not shrink on its
  own; the reading before is in the record.
- **Contracts with impact.ai.** The inventory format and the `impact.setup` span are a contract with the impact.ai
  service; change the service first, then this repository's code and tests.
- **No detection, scoring or guard logic in this repository.** Verdicts are computed by the impact.ai service; the kit
  collects and sends.
- **No outside contributions without a contributor agreement.**
- **Public and Apache-2.0.** Every source file of ours starts with `SPDX-License-Identifier: Apache-2.0` (`make licenses`
  adds it), and nothing internal reaches the repository, the chart or the images: internal hosts, e-mail addresses,
  account IDs, private addresses, tokens, increment ids and the names of private repositories. `make lint` and
  `make release` check both; a fixture value is allowed only by name, with a reason, in
  `scripts/check_internal_details.py`. That script names nothing of the company: its own hosts, environments and
  customers are in a deny-list kept outside the repository (`INTERNAL_DETAILS_DENYLIST=<file>` or `--denylist <file>`),
  and a test or fixture uses a fictitious name, never a real one split into pieces. The licenses of what the images bundle are generated by
  the build, never written by hand. `make ci` and `make release` stop on a fixable CRITICAL or HIGH vulnerability in an
  image (trivy).

## Delivery

- One branch and one pull request per change, titled with its outcome. Tests first; CI decides.
- CI logic lives in `Makefile` and `scripts/`, tool versions in `mise.toml`. `.github/workflows/*` change only through
  the code owner, so keep workflows calling `make` targets.
- A commit has an imperative subject and a body that says why. Records state decisions, not people.
